## Machine Learning > NHN Cloud Foundry > コンソールユーザーガイド { #foundry.console.guide }

このドキュメントでは、NHN Cloud Foundry コンソールでデータソース、パイプライン、分析（クエリ・チャート・ダッシュボード）、アプリを管理する方法を説明します。

!!! danger "注意"
    본 서비스 이용 시 개인정보가 포함된 정보를 입력하지 않도록 유의하여 주시기 바랍니다.
    본 서비스는 고객이 입력하는 개인정보에 대한 별도의 안전성 확보조치를 제공하지 않으므로, 개인정보가 포함된 정보의 입력 및 저장을 권장하지 않습니다.

設定項目の表の必須列は次を意味します。

- `O`: 必須入力項目
- `X`: 任意項目
- `O*`: 他の設定値によって必須かどうかが変わる項目

<a id="status"></a>
## 現況 { #status }

コンソールパス: **Machine Learning > NHN Cloud Foundry > 現況** タブ

現況タブでサービスの有効化状態とテナント設定を確認します。サービスを使用するには、まずこのタブで有効化状態を確認し、有効化されていない場合は有効化を申請する必要があります。

<a id="status.activate"></a>
### サービス有効化申請 { #status.activate }

サービスの有効化はコンソールから直接実行することはできません。[1:1 お問い合わせ](https://www.nhncloud.com/kr/support/inquiry)に希望するリソースサイズを含めてお問い合わせください。申請したクラスターが作成されると、データソースの作成から順番に使用できます。

リソースサイズ別に使用できる機能は次のとおりです。

| 値 | 説明 |
| --- | --- |
| SMALL | 基本リソース: データソース、共通機能、チャートクエリを使用可能 |
| MEDIUM | 基本 + データパイプラインを追加で使用可能 |
| LARGE | 基本 + AI アプリを使用可能 |
| XLARGE | すべての機能を使用可能（データパイプライン + AI アプリ） |

<a id="status.info"></a>
### サービス状態の確認 { #status.info }

有効化後は、現況タブで次の情報を確認できます。

| 項目 | 説明 |
| --- | --- |
| サービス状態 | 現在のサービスの有効化状態 |
| テナントドメイン | サービスにアクセスする際に使用するドメイン |

- 有効化後にリソース変更が必要な場合も、1:1 お問い合わせで申請します。
- サービス環境の構成または整理中は、進行状況が合わせて表示されます。
- **[無効化]** ボタンをクリックすると、サービスを無効化できます。

!!! danger "注意"
    サービスを無効化すると、作成されたすべてのリソースが削除され、この操作は元に戻すことができません。

<a id="datasource"></a>
## データソース { #datasource }

コンソールパス: **Machine Learning > NHN Cloud Foundry > データソース** タブ

データソースは、NHN Cloud Foundryで分析するデータを保存する単位です。データソースの作成、照会、削除はコンソールで行います。

<a id="datasource.list"></a>
### データソース一覧 { #datasource.list }

データソース一覧画面では、次の情報を確認できます。

| カラム | 説明 |
| --- | --- |
| タイプ | データソースの種類 |
| データソース名 | データソースを識別する名前 |
| テーブル名 | データが保存されるテーブル名 |
| 状態 | データソースの現在の状態 |
| データ量 | ロードされたデータの行数 |
| 作成日 | データソースが作成された日時 |
| 詳細 | 虫眼鏡アイコンをクリックすると詳細情報を照会 |

タイプ:

| 値 | 説明 |
| --- | --- |
| ファイル | アップロードしたCSVファイルで作成したデータソース |
| レコメンド | レコメンド結果が保存されるデータソース |
| データセット | パイプラインが作成したデータソース |

状態:

| 値 | 説明 |
| --- | --- |
| INITIALIZING | データソースの初期化中 |
| PROCESSING | データ処理中 |
| INGESTING | データロード中 |
| COMPLETED | データソースの処理完了 |
| FAILED | データソースの処理失敗 |
| DELETING | データソースの削除中 |

タイプがファイルのデータソースは、最新のファイルアップロード結果が状態の横にアイコンで合わせて表示されます。

| 値 | 説明 |
| --- | --- |
| 反映中 | 最近アップロードしたファイルを反映中 |
| 確認推奨 | 最近アップロードしたファイルは反映されましたが、確認が必要な項目があります。データソースの詳細で内容を確認してください |
| 確認必要 | データソースは使用可能ですが、最近アップロードしたファイルは未反映です。ファイルを確認後、再度アップロードしてください |

- ステータスバッジ横の疑問符アイコンにマウスを合わせると、ステータスの説明が表示されます。
- 上部の検索機能で、データソース名またはIDを基準にフィルタリングできます。
- タイプ・データソース名・テーブル名・状態カラムは、カラムヘッダーのフィルターでも絞り込みができます。
- ページあたりの表示件数を調整できます（10件、20件、50件 / デフォルト10件）。

!!! tip "ヒント"
    タイプがレコメンドおよびデータセットの項目は、ユーザーが直接作成することはできません。レコメンドはレコメンドシステムアプリを作成する際に、データセットはパイプラインを実行する際に自動的に作成されます。

<a id="datasource.create"></a>
### データソースの作成 { #datasource.create }

**[データソースの作成]** ボタンをクリックすると、作成モーダルが開きます。

<a id="datasource.create.basic"></a>
#### 基本設定 { #datasource.create.basic }

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| データソース名 | O | 韓国語、日本語、英字、数字、スペース、-、_ が使用可能（1〜64文字） |
| テーブル名 | O | 英小文字、数字、_ が使用可能（1〜64文字）。数字で始めることはできません。SQL予約語は使用できません |
| 説明 | X | データソースの説明 |

既に使用中のデータソース名とテーブル名は使用できません。

<a id="datasource.create.detail"></a>
#### 詳細設定 { #datasource.create.detail }

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| CSVファイル | X | **[ファイルを選択]** ボタンでアップロードするCSVファイルを選択します（最大100MB） |
| ヘッダー設定 | X | **[最初の行はヘッダーです]** にチェックを入れると、CSVの1行目をカラム名として使用します |
| 主キーフィールド | X | 行を識別するカラムをドロップダウンで指定します |
| スキーマ | O | データのフィールド名とタイプの定義 |

主キーフィールドは次のように指定します。

- CSVファイルを選択すると、最初のカラムでドロップダウンが自動的に作成されます。ドロップダウンをクリックして他のカラムに変更します。
- **[主キーを追加]** ボタンでドロップダウンを追加すると、2つ以上のカラムをまとめて指定できます。既に選択したカラムは、他のドロップダウンの候補に表示されません。
- ドロップダウンをすべて削除すると、主キーが未指定の状態になります。
- ヘッダーがないファイルは、カラムが順番と最初のデータ行の値で表示されます。

スキーマは次の方法で入力します。

- タイプ推論: CSVファイルを選択した後、**[タイプ推論]** ボタンをクリックすると、CSVの先頭サンプル（最大1,000行）からカラムタイプを推論し、スキーマ入力欄を自動で埋めます。誤って推論されたタイプはユーザーが直接修正します。
- テーブル編集: **[フィールドを追加]** ボタンで行を追加し、各行にフィールド名とタイプを指定します。備考欄にはタイプ推論の結果のうち確認が必要な項目が表示されます。
- JSON編集: **[JSONで直接編集]** ボタンをクリックし、以下の形式のJSON配列を直接入力します。

スキーマJSON形式の例:

```json
[
  { "fieldName": "hostname", "fieldType": "string" },
  { "fieldName": "portName", "fieldType": "string" },
  { "fieldName": "trafficIn", "fieldType": "double" },
  { "fieldName": "eventTimestamp", "fieldType": "timestamp" }
]
```

サポートするフィールドタイプ:

| 値 | 説明 |
| --- | --- |
| boolean | ブール値 |
| int | 整数（32bit） |
| long | 整数（64bit） |
| float | 実数（32bit） |
| double | 実数（64bit） |
| string | 文字列 |
| timestamp | タイムスタンプ |
| datetime | 日時（YYYY-MM-DD HH:MM:SS） |
| date | 日付 |
| array | 配列（基本） |
| array&lt;double&gt; | double配列 |
| array&lt;int&gt; | int配列 |
| array&lt;string&gt; | string配列（レコメンドモデル用） |
| array&lt;float&gt; | float配列（レコメンドモデル用） |

!!! danger "注意"
    予約フィールド名 `system_eventTimestamp` は使用できません。

設定完了後、**[追加]** ボタンをクリックするとデータソースが作成されます。

<a id="datasource.delete"></a>
### データソースの削除 { #datasource.delete }

一覧から削除するデータソースをチェックボックスで選択し、**[削除]** ボタンをクリックします。

- 削除するとテーブルとロードされたデータも一緒に削除されます。
- 収集作業が進行中の場合、削除できません。

<a id="datasource.detail"></a>
### 詳細表示 / プレビュー { #datasource.detail }

- **[詳細]**（虫眼鏡アイコン）: データソースの情報を確認します。
- **[プレビュー]**（⌄アイコン）: ロードされたデータをテーブル形式でプレビューします。

詳細表示は次のタブで構成されます。

| タブ | 説明 |
| --- | --- |
| 接続情報 | データソースID、データソース名、テーブル名、タイプ、説明、状態 |
| カタログ | フィールド名とデータ型の一覧照会、**[フィールドを追加]** |

<a id="datasource.edit"></a>
### データの更新 { #datasource.edit }

データソース名とテーブル名は、作成後に変更できません。ロードされたデータは新しいCSVファイルで更新し、フィールドは追加できます。

<a id="datasource.edit.csv"></a>
#### CSVによるデータ修正 { #datasource.edit.csv }

一覧でタイプがファイルのデータソース行のその他（⋯）メニューで **[CSVで修正する]** をクリックします。

1. 既存のカラム一覧を確認します。
2. **[ファイルを選択]** ボタンで新しいCSVファイルを選択します（最大100MB）。
3. 選択したファイルのプレビューと確認事項を確認します。
4. **[上書き]** ボタンをクリックするとアップロードが開始され、進捗は一覧画面で確認します。

アップロードが制限される場合は次のとおりです。

| 状況 | 案内 |
| --- | --- |
| ファイルのカラム数が既存のカラム数より多い | カタログにフィールドを先に追加してから再度アップロードしてください |
| カタログにないカラムが含まれている | カタログにフィールドを先に追加してから再度アップロードしてください |
| ヘッダー設定とファイルの先頭行が一致しない | カラム名行があるファイルでアップロードするか、データソースのヘッダー設定を変更してください |

<a id="datasource.edit.field"></a>
#### フィールドの追加 { #datasource.edit.field }

詳細表示の **[カタログ]** タブで **[フィールドを追加]** ボタンをクリックします。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| フィールド名 | O | 英字または_で始まり、英字、数字、_のみ使用可能 |
| タイプ | O | スキーマでサポートするフィールドタイプから選択 |
| 説明 | X | フィールドの説明 |

- **[行を追加]** ボタンで一度に最大20件まで追加できます。
- システム予約フィールド名および既存のフィールド名は使用できません。

!!! tip "ヒント"
    コンソールだけでなく、APIでもデータを更新できます。使用方法は [APIガイド](../api-guide/#ingest.api) の「Ingest API」を参照してください。

<a id="pipeline"></a>
## パイプライン { #pipeline }

コンソールパス: **Machine Learning > NHN Cloud Foundry > パイプライン** タブ

パイプラインは、データソースのデータをノードを接続したワークフローで処理し、分析可能なデータセットに変換する機能です。

<a id="pipeline.list"></a>
### パイプラインリスト { #pipeline.list }

パイプラインメニューに移動すると、作成済みのパイプラインの一覧がテーブル形式で表示されます。

| カラム | 説明 |
| --- | --- |
| チェックボックス | パイプラインの選択 |
| 有効化 | 有効/無効のアイコン |
| パイプライン名 | パイプラインを識別する名前 |
| バッチスケジュール | 設定されたスケジュール。未設定の場合はハイフンで表示 |
| 開始日時 | スケジュールの開始日時 |
| 終了日時 | スケジュールの終了日時 |
| 最終実行日時 | 最も直近の実行日時 |
| パイプラインステータス | パイプラインの現在の状態 |
| 手動実行 | 実行ボタン |

- 行をクリックすると、編集画面に移動します。
- 実行中のパイプラインは、手動実行の欄に進行中の表示が現れ、実行できない状態ではボタンが無効化されます。

ツールバーから、パイプラインの作成、修正、削除、有効化、無効化を実行できます。有効化と無効化は **[詳細(⋯)]** メニューにあります。

<a id="pipeline.create"></a>
### パイプライン作成 { #pipeline.create }

1. 一覧画面で **[パイプライン作成]** ボタンをクリックします。
2. 右側の **[設定パネル]** で基本情報を入力します。

    | 項目 | 必須 | 説明 |
    | --- | --- | --- |
    | パイプライン名 | O | パイプラインを識別する名前（最大 30 文字）。韓国語、日本語、英字、数字、スペース、-、_ が使用可能 |
    | パイプライン説明 | X | パイプラインの補足説明（最大 255 文字） |
    | タグ | X | 分類用のタグ（最大 10 個、各 50 文字） |

3. **[作成]** ボタンをクリックすると、パイプラインが下書き状態で作成されます。

!!! danger "注意"
    有効化済みのパイプラインの設定を保存すると、パイプラインが無効化されます。実行ボタンを押してビルドすると、自動的に有効化されます。

<a id="pipeline.editor"></a>
### パイプラインエディター { #pipeline.editor }

パイプラインの作成/編集時に表示されるメイン編集画面です。

- **[ヘッダー]**: パイプライン名、説明、戻るボタン
- **[タブバー（左側）]**: 実行/停止、実行履歴、ソースノード追加ボタン
- **[タブバー（右側）]**: 最終実行日時、ステータス/ビルド/有効化バッジ、保存ボタン
- **[エディター領域]**: ノード-エッジエディター（ドラッグアンドドロップ、自動整列サポート）
- **[サイドパネル]**: 設定、スケジュール、コンピューティングリソースパネル

<a id="pipeline.status"></a>
#### パイプラインステータス { #pipeline.status }

ステータスバッジにマウスを乗せると、ツールチップで詳細を確認できます。

| 値 | 説明 |
| --- | --- |
| 下書き | パイプラインが作成され、ノードがない状態 |
| 変更済み | パイプライン設定が変更され、再ビルド（実行）が必要な状態 |
| ビルド中 | パイプラインのビルド中 |
| 待機中 | パイプラインのビルドが完了し、実行準備が整った状態 |
| 実行中 | パイプラインの実行中 |
| 完了 | パイプラインの実行が正常に完了 |
| 失敗 | パイプラインの実行停止またはエラーが発生 |
| 停止済み | ユーザーがパイプラインの実行を停止した状態 |
| 削除中 | パイプラインの削除中 |

<a id="pipeline.node"></a>
### ノード構成 { #pipeline.node }

パイプラインは以下の 5 種類のノードを組み合わせて構成します。

| ノードタイプ | 役割 | 入力 | 出力 | 説明 |
| --- | --- | --- | --- | --- |
| Source（ソースノード） | データ元 | なし | データ | 外部データソースを接続 |
| Transform（変換ノード） | データ加工 | データ | 変換されたデータ | フィルター、派生カラム、集計、ラベルエンコーディングなど |
| Join（結合ノード） | テーブル結合 | 2 つのデータ | 結合されたデータ | Inner/Left/Right/Full Outer/Semi/Anti 結合 |
| Union（ユニオンノード） | テーブル統合 | 2 つのデータ | 統合されたデータ | Full Merge/Intersect Merge/Left-First Merge |
| Dataset（出力ノード） | 出力テーブル | データ | なし | テーブルとして結果を保存（最終ノード） |

接続の制約事項:

- SOURCE ノードには入力を接続できません（ルートノード）。
- DATASET ノードには出力を接続できません（最終ノード）。
- 循環参照（ループ）や自己との接続はできません。

!!! danger "注意"
    保存時にパイプライン構成を検査します。すべてのノードは 1 つのフローで接続されている必要があり（未接続ノード不可）、フローの最終ノードは 1 つの DATASET ノードでなければなりません。

<a id="pipeline.node.source"></a>
#### ソースノードの追加 { #pipeline.node.source }

1. タブバーの **[ソースノードの追加]** ボタンをクリックします。
2. 使用可能なデータソースの一覧がモーダルで表示されます。
3. 目的のソースを選択して追加します。

| 値 | 説明 |
| --- | --- |
| FILE | CSV ファイルデータソース |
| 推薦 | 推薦結果ストレージ |
| データセット | パイプラインのデータセットノードが生成したデータ。他のパイプラインの入力として再利用可能 |

<a id="pipeline.node.transform"></a>
#### 変換ノード(TRANSFORM) { #pipeline.node.transform }

変換作業ごとにノード名（最大 30 文字、韓国語・日本語・英字・数字・空白・`-`・`_`）を指定します。1 つのノードに複数の変換作業を追加すると、順番に接続されたノードが生成されます。

サポートされる変換メソッドは次のとおりです。

| 分類 | メソッド | 説明 |
| --- | --- | --- |
| Row（行単位演算） | Filter | 条件に一致する行のみ抽出 |
| Row（行単位演算） | Explode | 区切り文字列を行に分解 |
| Row（行単位演算） | Derive | ホワイトリスト関数で派生カラムを生成 |
| Aggregation（集計演算） | Aggregate | グループ化および集計 |
| Window（ウィンドウ演算） | Rank Top N | グローバル並べ替え＋上位 N 件 |
| Column（カラム演算） | Label Encode FIT | カテゴリ → 整数マッピングテーブルの生成 |
| Column（カラム演算） | Label Encode Apply | マッピングテーブルによるエンコードの適用 |
| LLM（LLM ベースの演算） | Classify | LLM でテキストをカテゴリに分類 |

<a id="pipeline.node.transform.filter"></a>
##### フィルター(Filter) { #pipeline.node.transform.filter }

| 値 | 説明 | 例 |
| --- | --- | --- |
| = | 等しい | field = 'value' |
| ≠ | 等しくない | field ≠ 'value' |
| > | より大きい | field > 100 |
| ≥ | 以上 | field ≥ 100 |
| &lt; | 未満 | field < 100 |
| ≤ | 以下 | field ≤ 100 |
| LIKE | パターンマッチング | field LIKE '%keyword%' |
| IN | リストに含む | field IN ('a', 'b', 'c') |
| IS NULL | NULL かどうか | field IS NULL |
| IS NOT NULL | NOT NULL かどうか | field IS NOT NULL |

選択したカラムのタイプによって、使用可能な演算子のみが表示されます。

| カラムタイプ | 使用可能な演算子 |
| --- | --- |
| 文字列 | =, ≠, LIKE, IN, IS NULL, IS NOT NULL |
| 数値 | =, ≠, >, ≥, &lt;, ≤, IN, IS NULL, IS NOT NULL |
| 日付/時刻 | =, ≠, >, ≥, &lt;, ≤, IS NULL, IS NOT NULL |
| ブール値 | =, ≠, IS NULL, IS NOT NULL |

比較する値は **[直接入力]**、**[時刻（現在基準）]**、**[別のカラム]** の中から選択します。

論理演算子は `AND`、`OR` をサポートしており、**[グループの追加]** ボタンで条件を最大 3 段階までグループ化できます。

<a id="pipeline.node.transform.explode"></a>
##### 分解(Explode) { #pipeline.node.transform.explode }

区切り文字でつながれた文字列カラムをトークンごとに別の行に分解します。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 分解するカラム | O | 区切り文字でつながれた文字列が含まれるカラム |
| 出力カラム名 | O | 分解された各トークンを格納するカラム名 |
| 区切り文字 | O | デフォルトはカンマ（,） |
| 空白の削除 | X | ON の場合、各トークンの前後の空白を削除 |
| 空トークンの削除 | X | ON の場合、分解後の空文字列トークンを行から除外 |
| 出力タイプ | X | STRING、BIGINT、INT、DOUBLE。未指定の場合は STRING |
| 保持する元カラム | X | 結果に含める元のカラム。選択しない場合はすべての元カラムが保持される |

- 区切り文字は正規表現として解釈されるため、特殊文字はエスケープが必要です（例: `\.`、`\|`）。
- 出力タイプを指定すると、分解された値が該当タイプに変換されます。例えば、数値 ID がカンマで区切られている場合に BIGINT を指定すると、結合キーのタイプを合わせることができます。

<a id="pipeline.node.transform.derive"></a>
##### 派生カラム(Derive) { #pipeline.node.transform.derive }

提供されている関数を使用して、既存のカラムから新しいカラムを作成します。**[派生カラムの追加]** ボタンで定義を複数追加でき、各定義に関数と派生カラム名を指定します。

| 値 | 説明 | 追加設定 |
| --- | --- | --- |
| DATE_BUCKET | 日付バケット（epoch ms → 指定タイムゾーンの日付） | ソースカラム、タイムゾーン（例: Asia/Seoul） |
| JSON_ARRAY_LENGTH | JSON 配列の要素数 | ソースカラム、要素スキーマ |
| CONCAT | 複数のカラムを区切り文字で結合 | ソースカラム 2 つ以上、区切り文字、デフォルト値（任意） |
| RATIO | 分子/分母の比率計算 | 分子、分母、倍数（任意、デフォルト 1）、丸め桁数（任意） |
| COALESCE | 複数カラムのうち最初の non-null 値 | ソースカラム 2 つ以上 |

- 定義は上から下へ順番に適用され、前に作成した派生カラムを後の定義のソースカラムとして参照できます。
- 派生カラム名には英字、数字、アンダースコア（_）、韓国語文字を使用できます。

<a id="pipeline.node.transform.aggregate"></a>
##### 集計(Aggregate) { #pipeline.node.transform.aggregate }

1. **[グループ化基準の選択]**（任意）: 同じ値を持つ行をグループにまとめます。選択しない場合は、全データを 1 つのグループとして集計します。
2. **[集計関数の定義]**（必須）: 集計するカラム、集計関数、結果カラム名を指定します。複数追加できます。

| 値 | 説明 |
| --- | --- |
| COUNT | 件数 |
| COUNT_DISTINCT | 一意の値の件数 |
| SUM | 合計 |
| AVG | 平均 |
| MIN | 最小値 |
| MAX | 最大値 |
| FIRST | 最初の値 |
| LAST | 最後の値 |
| STDDEV | 標準偏差 |
| VARIANCE | 分散 |
| ARRAY_AGG | グループの値を配列として収集 |

- COUNT は集計するカラムとして `* (全体)` を選択できます。
- FIRST と LAST は並べ替え基準カラムと方向（昇順/降順）を指定し、並べ替え後の最初または最後の値を取得します。

ARRAY_AGG を選択すると、次の設定が追加されます。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 配列要素の種類 | O | 単一カラムまたは JSON オブジェクト |
| 収集するカラム | O* | 配列要素の種類が単一カラムの場合に必須。配列に格納するカラム |
| JSON オブジェクトフィールドの定義 | O* | 配列要素の種類が JSON オブジェクトの場合に必須。キー名とカラムの組み合わせ |
| 配列要素の並べ替え | X | 並べ替え基準カラムと方向。未指定の場合は並べ替えなし |
| 出力形式 | O | STRUCT_ARRAY、JSON_STRING_ARRAY、JSON_STRING |
| 重複除去（DISTINCT） | X | 並べ替えを設定すると無視される |

<a id="pipeline.node.transform.rank"></a>
##### ランキング(Rank Top N) { #pipeline.node.transform.rank }

全データを指定した基準で並べ替え、上位 N 行のみを残します。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 並べ替え基準 | O | 並べ替えるカラムと方向（DESC / ASC） |
| 上位 N 件 | O | 並べ替え後に結果に含める行数 |
| 結果順位カラム名 | O | 結果に追加される 1〜N の順位カラムの名前 |

- **[並べ替え基準の追加]** ボタンで基準を複数指定すると、第 1 ソート、第 2 ソートの順に適用され、ドラッグして順序を変更できます。
- 参照時に順位カラムで並べ替えると、元の順序を維持できます。

<a id="pipeline.node.transform.label.encode"></a>
##### ラベルエンコーディング(Label Encode FIT / Label Encode Apply) { #pipeline.node.transform.label.encode }

カテゴリ型データを数値（整数）に変換する機能です。**FIT（学習）** と **APPLY（適用）** の 2 段階で構成され、必ず FIT ノードを先に作成してから APPLY ノードで参照する必要があります。

FIT ノード設定:

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| エンコードするカラムの選択 | O | ラベルエンコーディングを適用するカラム（1 つ以上） |
| 開始インデックス | X | エンコードの開始値（デフォルト: 0） |

APPLY ノード設定:

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| マッピングテーブルノードの選択 | O | FIT ノードを選択 |
| 元カラムの上書き | X | チェック時、元カラムをエンコードされた値に置き換える（デフォルト: 無効） |
| 結果カラムのサフィックス | X | 元カラムを保持する場合に新カラム名に付くサフィックス（デフォルト: _encoded） |

!!! tip "ヒント"
    マッピングテーブルにない値（OOV、Out-of-Vocabulary）は `-1` としてエンコードされます。

!!! danger "注意"
    FIT を再実行すると、データの変更によりエンコード番号が変わる場合があります。既存モデルとの互換性に注意してください。

<a id="pipeline.node.transform.classify"></a>
##### 分類(Classify) { #pipeline.node.transform.classify }

LLM を使用してテキストカラムの値をカテゴリに分類します。分類の基準となるカテゴリリストは、別のデータソースノードとして準備する必要があります。

パイプラインが実行されると、入力データの行をバッチサイズ分まとめて、バッチごとに 1 回 LLM を呼び出します。各呼び出しのプロンプトにはカテゴリリストと該当バッチの行が含まれ、LLM が行ごとに適切なカテゴリ ID を返すと、その結果が分類結果カラムとして保存されます。

**LLM 設定**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| LLM プロバイダー | O | Claude |
| モデル名 | O | claude-haiku-4-5、claude-sonnet-4-6 |
| API キー | O | 使用する LLM の API キー。このパイプラインにのみ保存され、保存後は再表示されません |
| バッチサイズ | X | 1 回の LLM 呼び出しに含める行数（1〜30） |
| 最大リトライ回数 | X | 呼び出し失敗時のリトライ回数（0〜10） |
| タイムアウト（秒） | X | 呼び出し待機時間（1〜600） |
| 増分分類 | X | 変更された行のみ LLM で分類し、変更のない行は前回の実行結果を再利用 |

**入力カラム**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 入力カラム | O | LLM に渡すカラム。複数選択可 |
| カラム結合区切り文字 | X | 複数の入力カラムの値を連結する際に使用する区切り文字 |
| ユーザープロンプトテンプレート | X | 行ごとの入力値の構成テンプレート。{{ カラム名 }} パターンが該当カラムの値に置換され、設定すると結合区切り文字より優先して適用されます。入力カラムで選択したカラムのみ参照可能 |

**軸（カテゴリテーブル）**

分類の基準となるカテゴリリストを軸として登録します。軸は最大 5 つまで追加できます。

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| カテゴリノード | O | カテゴリリストが含まれるデータソースノード |
| カテゴリ ID カラム | O | カテゴリを識別するカラム |
| カテゴリ名カラム | O | カテゴリ名カラム |
| カテゴリメタデータカラム | X | カテゴリの説明、判定基準などの追加カラム。プロンプトとともに渡され、分類精度を向上 |
| 分類結果カラム（配列） | O | 分類結果を格納する配列カラム名 |
| 代表カラム | X | 最も代表的な分類 ID を保存するカラム名。空白にすると生成しない |

**出力**

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| 出力タイプ | O | SINGLE_LABEL、MULTI_LABEL |
| 分類根拠カラム | X | LLM が提供した分類根拠を保存するカラム名。空白にすると根拠を要求しないためトークンコストを削減 |
| コンテンツ根拠カラム | X | 入力コンテンツから生成した短い説明を保存するカラム名 |
| コンテンツ根拠の最大長 | X | コンテンツ根拠カラムの最大文字数（1〜200） |

**システムプロンプト**（任意）: LLM に役割と分類基準を指示します。設定しない場合はデフォルトのプロンプトが使用されます。

!!! danger "注意"
    処理する行数が多いほど、LLM の呼び出し回数とトークン使用量が比例して増加し、コストが増加します。大規模データは先に小規模で検証してコストと品質を確認してから適用してください。

<a id="pipeline.node.join"></a>
#### 結合ノード(JOIN) { #pipeline.node.join }

2 つのデータストリームを結合します。

| 項目 | 必須 | 説明 |

<a id="pipeline.node.dataset"></a>
#### データセットノード(DATASET) { #pipeline.node.dataset }

パイプラインの最終出力ノードで、処理されたデータをテーブルとして保存します。

<a id="query"></a>
## 分析 - クエリ { #query }

コンソールパス: **Machine Learning > NHN Cloud Foundry > 分析** タブ > **クエリ** タブ

SQL を使用して、データソースのデータを照会・分析します。

<a id="query.run"></a>
### クエリ実行 { #query.run }

1. **[データソース]** を選択します。
2. **[クエリ選択]** で保存済みクエリを読み込みます。選択したデータソースで保存したクエリがある場合は一覧に表示されます。読み込まずに直接記述することもできます。
3. クエリ入力欄に SQL を記述します。
4. **[行制限]** を選択します（10、100、1,000、10,000、100,000 / デフォルト 1,000）。
5. **[クエリ実行]** ボタンをクリックします。

- 実行結果はデータグリッド形式で表示されます。カラム構造はクエリ結果に応じて動的に生成され、ページネーションをサポートします。
- データソースを選択すると、クエリ入力欄の右側にスキーマパネルが表示され、フィールド名とデータ型を確認できます。フィールド名で検索できます。
- クエリ入力欄で **Ctrl+Enter**（macOS は **⌘+Enter**）を押すとクエリが実行されます。
- クエリの実行に失敗した場合、失敗の原因が結果エリアに表示されます。
- **[初期化]** ボタンをクリックすると、記述したクエリがクリアされます。
- **[クエリ結果のダウンロード]** ボタンをクリックすると、結果が CSV ファイルとして保存されます（ファイル名: `クエリ名_日付_時刻.csv`）。
- FROM 句には、データソース一覧に表示されたテーブル名をそのまま使用します（`SELECT * FROM {テーブル名}`）。
- 単一の SELECT 文のみ実行できます。それ以外の文は拒否されます。

<a id="query.save"></a>
### 保存済みクエリの変更 { #query.save }

**[クエリ選択]** で読み込んだクエリの内容を変更した後、**[クエリ保存]** ボタンをクリックすると変更が保存されます。読み込んだクエリがない場合や内容を変更していない場合は、ボタンが無効になります。

<a id="query.list"></a>
### クエリ一覧 { #query.list }

クエリは実行のたびに実行履歴として自動的に記録されます。繰り返し使用するクエリはクエリ一覧に直接登録しておくことができます。**[クエリ一覧]** ボタンをクリックすると、保存済みクエリを管理するモーダルが開きます。

| カラム | 説明 |
| --- | --- |
| クエリ名 | 保存時に指定した名前 |
| クエリ構文 | 保存済みの SQL |
| 保存日時 | クエリを最後に保存した日時 |

アプリのステータスバッジにマウスを重ねると、ツールチップで詳細説明を確認できます。

| 値 | 説明 |
| --- | --- |
| 初期化中 | アプリの初期化が進行中 |
| 学習中 | AIモデルの学習が進行中 |

    アプリ作成直後に実行される学習・デプロイはアプリを準備するプロセスであり、この時点では推薦モデルはまだ学習されていない状態です。推薦APIを呼び出すと応答は返されますが、学習済みモデルの推薦結果ではありません。
    最初の学習はバッチスケジュールに設定した時刻に実行され（ステータス: 学習中 → デプロイ中 → アクティベーション中 → アクティブ）、学習済みモデルがデプロイされた後から有効な推薦結果を取得できます。

<a id="app.create.detail.model"></a>

<a id="app.detail.recommend"></a>
#### 推薦API呼び出し { #app.detail.recommend }

推薦リクエストのパラメータを入力して推薦APIを直接呼び出し、結果を確認できます。画面は入力フォーム、リクエストプレビュー、推薦結果の3つの領域で構成されています。

入力フォーム:

| 項目 | 説明 |
| --- | --- |
| 推薦アプリID | 呼び出し対象のアプリID。現在のアプリが自動入力されます |
| ユーザーID | 推薦対象のユーザーを選択 |
| 推薦モード | Sequential（履歴ベース）、Cold Start（属性ベース）から選択 |
| 最大推薦数 | レスポンスに含める最大アイテム数（1〜100、デフォルト値10） |
| Longtail モード | 人気のないアイテムも含めて推薦の多様性を向上。Cold Startモードでは使用できません |
| context | 推薦リクエストのコンテキスト情報（現在・最近閲覧したアイテムなど）をフィールド単位で追加 |
| userAttributes | ユーザー属性情報（グループ、年齢、関心事など）をフィールド単位で追加 |
| options | 推薦リクエストのオプションをフィールド単位で追加 |

- **リクエストプレビュー**: 入力値で構成された実際のAPIリクエストJSONを表示します。**[コピー]** ボタンでコピーしてAPI連携開発に活用できます。
- **推薦結果**: **[推薦リクエスト]** ボタンをクリックすると、順位、アイテムキー、スコアおよび推薦理由が表示され、総結果数とレスポンス時間も合わせて確認できます。

!!! tip "ヒント"
    推薦APIの呼び出しは、アプリがアクティブな状態のときのみ可能です。

<a id="app.detail.info"></a>
#### アプリ情報 { #app.detail.info }

アプリID、アプリ名、ステータス、アプリタイプ、説明、作成日、更新日、バージョン、および入出力データソースを確認できます。

- 入力データソース: モデルの学習に使用するデータソースです。推薦アプリはモデルごとに分けて表示されます。
- 出力データソース: 推薦結果が保存されるデータソースです。
